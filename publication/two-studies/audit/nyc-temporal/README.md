# Does the common menu comparison transfer to other NYC catalogues?

This is a secondary check of the paper's first-five versus uniform-five comparison, using the existing temporal split, independent seed ranges relative to the pilot, and the evaluation donor pool. Each renter's first five chosen by the analyst use the modeled order including latent tastes. The archived hosted-model pilot remains a separate comparison. The periods and block counts came from the prior stage-2 market configuration. The choice to use these markets for this comparison and to add the affordability-band arm followed the development analysis. PLAN.md was recorded locally before computing these outcomes.

The unit is a simulated renter instance. Both outcomes use everyone in each supported sample. Before outcomes, the market generator removed identifiable listings overlapping development and earlier months of the same evaluation period, with ambiguous records retained and reported. It used the separate evaluation subset of the same Census release. Core inputs, including preference coefficients and development references for features and geography, were held fixed. The citywide lower-income threshold and geographic weights use the common survey. Each primary seed (1000–1399) or replication seed (1000–1099) indexes all its region-months. Simulated markets can reuse households and ads. Both autumn catalogues contain unusually low collection volume on some days; the five dates analyzed here do not represent random draws from other years or cities.

All five boroughs were attempted in each month. Staten Island had fewer than 64 ads throughout. Physical-unit deduplication left 29 eligible lower-price ads against the 32 required in Manhattan in September 2026, so that enriched cell is unavailable. Rates renormalize the original equal-month and Census borough weights across supported borough-months. Comparing the two inventory designs on the same seven fall cells changes the ordinary estimates to +20.96 and −14.60 points. The signs hold within all 39 supported period/design/borough/month cells.

For the random menus, exact expected partner coverage is the sum of min(5,d)/d over full-list recipients with d feasible options. For placements, each market uses 48 uniform random menus and 48 DA replays. The 10,000-draw pointwise percentile intervals resample complete simulation seed blocks. They quantify variability in simulation conditional on the catalogs and chosen model. Conditional Monte Carlo SE for averaging random-menu placements varies from 0.0057 to 0.0111 percentage points across panels. Neither set of uncertainties assesses error in the assumed housing preferences or simultaneous availability. FirstMover records how an ad first appeared and omits subsequent status and price changes. Only the school study has recorded offers. ## Reproduction

From the full project repository, prepare the original ACS data and eight FirstMover clean monthly catalogues described in its data pipeline. The eight months are June–August 2025 and June–October 2026. For each firstmover CSV, compare the raw SHA-256 against the corresponding data/firstmover/raw/YYYY-MM.manifest.json, then use scripts/firstmover_clean.py. Install the repository's Python requirements, including NumPy and pandas. A clean directory may be supplied with --clean. The default is the project's data/firstmover/clean directory.

    python /path/to/temporal_benchmark.py --repo . --output /tmp/nyc-temporal --workers 4
    python /path/to/verify_temporal.py --repo . --output /tmp/nyc-temporal

Multiprocessing with more than one worker uses POSIX fork. Using --workers 1 runs the same study serially. The public artifact contains aggregate outputs. No public file contains individual records, assignments, or raw advertisements. temporal-markets.csv.gz gives one row per planned market, including unsupported draws. The first axis of temporal-draws.npz corresponds to those rows in order, the second to random menu draws, and the third to full-partner coverage and placements. Unavailable rows use −1 in the draw array. temporal-summary.csv gives all endpoint levels and pointwise intervals. temporal-support.csv gives every excluded cell and reason. temporal-common-support.csv compares matched geography. temporal-receipt.json records source, code, and market provenance.

The second checker recomputes weighted means independently and, for the first seed in each of the 39 supported cells, regenerates markets with the unmodified feature implementation, selects each random menu by a separate routine, and runs both serial and synchronous DA. All 124,800 applicant assignments agree (39 markets, 50 menus per market, 64 applicants). Every archived aggregate is consistent with the checked rows. temporal-verification.json identifies the verified files by SHA-256.
